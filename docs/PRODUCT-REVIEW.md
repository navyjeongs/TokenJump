# TokenJump 기능 및 배포 검토

이 문서는 개발 중 검토와 변경 이력입니다. 앞부분에는 이전 동작이 남아 있으며, 현재 기능·조작·비용은 [README](../README.md)를 기준으로 확인하세요.

검토일: 2026-10-21. 무료 배포 앱에서 브랜드 캐릭터를 사용할 수 있는지와 무료 AI 계정 연동을 별도로 구분한다.

## 현재 기능

- macOS 14+ 메뉴바 팝오버, A/D·방향키 이동, Space/W/위 방향키 점프.
- Esc·바깥 클릭·다른 앱 전환으로 닫고 게임 정지. 메뉴바 정사각형 아이콘 1개, 스테이지 화면 고정.
- 12개 이름 있는 스테이지. 스테이지 선택 가능. GOAL 착지로 클리어, N으로 다음 스테이지. 마지막 스테이지는 전체 클리어 표시.
- 재시작은 R. 실패하면 마지막 발판 복귀. 점프에 사용한 토큰은 환급하지 않음.
- 자체 도형 캐릭터 Bit(로봇), Ember(여우), Orbit(외계인). 외부 이미지 다운로드/라이선스 의존성 없음. 캐릭터 선택과 스테이지 번호 저장.
- 기존 저장 데이터와 호환. Codex·Claude Code 로컬 로그를 60초 간격으로 읽고 토큰 잔액 저장.
- 체험 모드는 별도 저장소이며 앱을 열 때 연습용 200,000토큰을 제공. 난이도에 따라 표시 점프 횟수가 달라짐.

## 난이도 기본값

| 난이도 | 토큰 / 점프 1회 | 발판 폭 | 기본 세로 간격 | 스테이지당 최소 소비 |
|---|---:|---:|---:|---:|
| 쉬움 | 5,000 | 120pt | 72pt | 20,000 |
| 보통 | 10,000 | 90pt | 85pt | 40,000 |
| 하드 | 25,000 | 60pt | 95pt | 100,000 |

스테이지마다 간격을 기본값의 80~100%로 조절한다. 난이도 변경은 현재 스테이지를 처음부터 시작하지만 토큰 잔액은 보존한다. 낮은 난이도에서 받은 점프를 하드로 가져오는 방식이 아니라, 실제 남은 토큰으로 점프 가능 횟수를 다시 계산한다. 캐릭터 간 성능 차이는 없다.

이 값은 첫 밸런스 기준이다. 입력·출력·캐시 토큰 규모는 서비스와 작업에 따라 크게 달라지므로, 실제 사용 자료를 모아 보통 사용자에게 스테이지 1개가 얼마나 걸리는지 확인한 뒤 조정한다. 현재 구독료나 사용 한도 %로 환산하지 않는다.

## 검증

`./build-app.sh` 후 `.build/release/TokenJump --self-test` 및 `--game-test`.

- 최초 실행 기준점, 증가량, 동일 로그 반복 조회, Claude 메시지 중복, 차감 및 저장 복원.
- 난이도 변경 시 잔액 보존, 기존 저장 데이터 호환, 캐릭터/스테이지 저장.
- 실제 Game 로직으로 12 × 3 = 36개 조합 완주, 144번 점프·착지.
- 좌우 입력과 점프 동시 처리, 4회분 정확한 차감, 클리어 후 추가 차감 없음, 잔액 부족 시 점프 거부, 정지 시 입력 해제, 카메라 없는 고정 화면.

이 검증은 앱 내부 통합 테스트다. macOS에서 바깥 클릭으로 닫기, 팝업 선택 후 키보드 포커스, 화면 배치 등은 별도 UI 확인이 필요하다. 실제 배터리/메모리 벤치마크는 아직 수행하지 않았다.

## 서비스 캐릭터와 상표

무료 앱이라는 사실만으로 상표/로고를 캐릭터로 재사용할 권한이 부여되지는 않는다. 다음 내용은 공개 지침에 따른 제품 설계 판단이며 사용 허락을 받은 상태가 아니다.

- **Claude / Anthropic**: 공개 지침은 구체적 허용 및 자료 사전 승인을 요구하고, 색상·비율 등을 포함한 로고 변형을 허용하지 않는다. 로고에 눈·팔다리를 붙여 캐릭터화하는 안은 승인 전 기본 제공하지 않는다.
  - https://www.anthropic.com/legal/trademark-guidelines
- **ChatGPT / OpenAI**: 서비스와 직접 관련된 정확한 사용, 원형 유지, 소유권 표시, 제휴 오인 방지가 요구된다. 로고 변형이나 자체 브랜딩 편입은 지침에 맞지 않는다. 지원 서비스 표시와 게임 캐릭터화는 구분한다.
  - https://openai.com/brand/
- **Grok / xAI**: 서비스의 정확한 지칭으로만 사용하고 제휴를 암시하면 안 된다. 로고는 제공된 원본 그대로 사용해야 하며 변형은 허용되지 않는다. 캐릭터화에 대한 명시적 허용을 확인하지 못했다.
  - https://x.ai/legal/brand-guidelines

**현재 선택:** 자체 캐릭터 3종을 제공한다. 서비스 명칭은 연동 대상 안내로만 사용하고, 해당 서비스 공식 캐릭터나 제휴 상품인 것처럼 표시하지 않는다. 서비스별 로고 캐릭터가 필요하면 실제 시안을 만든 뒤 권리자에게 용도와 배포 방식을 명시하여 승인을 확인한다.

## 무료 AI 계정과 연동

- 현재 앱이 읽는 것은 Claude Code / Codex의 로컬 세션 파일이다. 계정의 유료 여부를 판별하거나 API 호출로 새로운 요금을 발생시키지 않는다.
- 지원 형식의 로컬 토큰 로그가 있다면 그 기록을 집계한다. 구독 플랜의 제공 범위는 별도이며 이 구현이 무료 계정에서 각 도구의 사용 권한을 보장하는 것은 아니다.
- 브라우저의 무료 ChatGPT·Claude·Grok 채팅은 현재 수집 대상이 아니다. 웹 UI를 이용했다고 이 앱에 토큰이 자동 충전되지 않는다.
- Grok 사용량 파서는 아직 구현하지 않았다. 서비스별 요금제/로그 제공 여부를 확인해 지원 대상을 결정해야 한다.
- 따라서 이번 무료 서비스 검토를 '모든 무료 AI 채팅의 토큰을 추적할 수 있다'는 의미로 받아들이면 안 된다. 미지원 소스는 앱 안내에 명시한다.

## 남은 제한

- 로그 복사·포크·회전에 대한 완전한 중복 방지는 보장하지 않음. 읽는 로그가 있는 로컬 기기의 기록 기준이다.
- 커스텀 로그 경로, 여러 계정/장치 통합, Grok, 웹 채팅 수집 미지원.
- 스테이지 번호는 저장하지만 실행 종료 전 정확한 발판 위치는 복원하지 않음.
- 자동 플레이 검증과 실제 UI 확인은 구분하여 기록한다.

## 발판 충돌과 장애물 (2026-10-21)

아래로 떨어질 때만 착지하는 단방향 발판은 일반적인 플랫폼 게임 설계 옵션이다. 모든 수직 점프 게임이 같은 규칙을 쓰는 것은 아니다. 확인한 게임 설명/개발자 답변과 엔진 문서를 구분한다.

- Godot 공식 CollisionShape2D 문서: 한쪽 면만 충돌시키는 one_way_collision을 지원한다. https://docs.godotengine.org/en/stable/classes/class_collisionshape2d.html
- Doodle Jump 개발사 Lima Sky의 스토어 설명: 부서지는/움직이는/사라지는/폭발하는 발판 및 UFO·블랙홀·몬스터를 별도 요소로 둔다. 이 설명만으로 모든 발판의 세부 충돌 규칙을 단정하지 않는다. https://play.google.com/store/apps/details?id=com.lima.doodlejump&hl=en
- Jump King 개발자 AMA: 원작 Tower 구간의 full-jump wall-bounce를 언급한다. 벽 충돌이 경로 설계에 활용되는 예다. https://www.reddit.com/r/PS4/comments/hgb0nr/

현재 구현:

- 얇은 보라/노란 발판: 아래와 옆에서 통과, 위에서 내려오면 착지.
- 3번 스테이지부터 회색 두꺼운 벽: 좌우·머리 충돌, 상단 착지. 우선 측면 안전 경로 밖에 배치해 충돌 규칙을 익히게 한다.
- 5번 스테이지부터 빨간 마름모 위험물: 접촉 시 마지막 발판 복귀, 추가 토큰 차감 없음. 사용한 점프 토큰은 환급하지 않는다.
- 움직이는 적/가시/주 경로를 막는 퍼즐 장애물은 아직 구현하지 않았다.
- 자동 플레이 36개 조합이 계속 통과하며, 별도로 벽 좌우·머리·상단 충돌, 위험물 복귀 시 잔액 보존, 단방향 발판의 상승 통과·하강 착지를 검증했다. 실제 UI 육안 검증은 별도다.


## 착지 및 메뉴바 개선

- 점프 수를 메뉴바에 쓰던 100pt 영역을 제거하고 macOS 기본 정사각형 상태 아이콘 하나로 축소. 18×18pt 템플릿 벡터로 라이트/다크 모드 대응. 원본은 Assets/TokenJump.svg, 앱은 동일한 도형을 AppKit 벡터로 그린다.
- 팝오버 높이 670→600pt. 스테이지·난이도·캐릭터·종료는 톱니바퀴 메뉴 안으로 이동. 설정 메뉴가 열려 있을 때 게임을 멈춘다.
- 중력을 먼저 적용하고 위치를 이동하던 근사식을 등가속도 적분으로 변경. 30FPS에서도 점프 높이가 낮아지지 않는다.
- 발이 발판 윗면을 지나는 시점의 가로 위치로 착지 판정. 가장자리 착지와 미세한 부동소수점 오차를 보정.
- 착지 120ms 전 점프 입력을 보관하고, 발판에서 벗어난 직후 80ms의 점프 여유 제공. 실제 점프할 때만 토큰 차감, 연타/버퍼로 중복 차감하지 않음.
- 12개 스테이지 × 3개 난이도 × 30/60/120FPS = 108회 완주와 432회 착지 검증. 30FPS 가장자리 착지·착지 직전 입력·아이콘 크기/템플릿 검사도 통과. 실제 macOS UI 육안 검증은 별도.


## 대포 구간과 두 탭 UI

- 상단 왼쪽 **게임**, 오른쪽 **사용량**. 사용량 탭은 게임과 포탄 시간을 멈추며 숨겨진 게임에 키 입력이 전달되지 않는다. 다시 게임으로 돌아가면 같은 위치/포탄 상태에서 이어진다.
- 4~12 스테이지는 좌우 대포가 번갈아 발사한다. 주황 선으로 발사 0.8초 전 예고. 첫 발사 1.5초 후, 반복 간격은 쉬움 3.4초 / 보통 2.7초 / 하드 2.1초. 포탄은 장면 밖으로 나가면 제거한다.
- 피격은 토큰을 직접 차감하지 않고 진행 방향으로 밀어낸다. 0.8초 연속 피격 보호. 피격 후 공중 Space 회복은 점프 1회를 소모하며, 잔액이 없으면 실행할 수 없다. 착지하면 공중 회복 상태가 해제된다.
- 대포 구간 첫 출발에는 쉬움 5회 / 보통 6회 / 하드 8회의 잔액이 필요하다. 맵 기본 4회에 회복 여유를 더한 제품 설정이다. 1회만 남았다면 출발하지 않고 토큰을 모아야 한다. 잔액 기준을 통과하면 미리 전체를 차감하지 않고 실제 점프할 때마다 1회씩 소비한다.
- 대포 구간에서 화면 아래로 추락하면 해당 스테이지 출발점으로 복귀하며 출발 잔액 조건을 다시 확인한다. 소비한 토큰은 환급하지 않는다. 출발 전에도 대포는 발사하지만 포탄 경로는 시작 발판 위에 있어 대기 중인 캐릭터는 안전하다.
- 사용량: 남은 점프, 보유 토큰, 점프에 소비한 토큰, Codex/Claude Code별 집계, 다음 점프까지 진행도. 통계 추가 이후 새로 읽은 기록 기준이며 기존 잔액의 전체 과거 사용량을 복원한 값은 아니다. 실제 AI 소모와 게임 안에서 쓰는 토큰은 구분해서 표시한다.
- 체험 모드와 실제 모드 저장소는 계속 분리된다. 원래 저장 데이터에서 새 통계가 없으면 0부터 집계한다.
- 검증 명령: `--self-test`, `--game-test`, `--combat-test`, `--ui-test --demo`.
- 기본 플랫폼 108개 조합 테스트는 대포를 끄고 경로/착지를 검증한다. 별도 대포 테스트는 3개 난이도의 출발 차단·발사 예고·양방향 발사·실제 반동 이동·공중 회복 차감·무적 시간·잔액 부족을 검증한다. UI 내부 검증은 두 탭/영역/표시값/정지/숨김 키 입력을 검증하며, 실제 OS 화면 육안 확인과는 다르다.


## 걷기 추락 / 대포 표시 수정

- 발판 위에 서 있던 프레임은 이동 후 가로 위치로 지지 여부를 판정한다. 실제 낙하 중 윗면을 통과할 때만 이전/현재 위치를 보간한다. 이 구분이 없으면 가장자리 보정이 캐릭터를 계속 붙잡는 문제가 있었다.
- 점프하지 않아도 발판 양쪽 끝에서 걸어 나가면 중력으로 떨어진다. 기존 화면 아래 추락 시 복귀 정책과 점프 잔액은 유지한다.
- 대포 발사를 첫 점프에 종속시키지 않는다. 4번 이후 스테이지가 활성화되면 대기 중에도 예고 후 좌우 발사한다. 사용량 탭/팝오버 닫힘은 계속 시간을 멈춘다.
- 대포를 바퀴·원형 본체·주황색 포신·검은 포구로 표시하고, 발사 섬광과 18px 포탄/꼬리를 추가했다. 회색 직사각형 벽과 구분된다.
- 양쪽으로 걷기만 해서 추락하는지 30/60/120FPS에서 검사. 대기 중 발사와 잔액 보존 및 기존 충돌/잔액/UI 테스트 통과. UI 육안 검증과 자동 검증은 구분한다.

## 최신 스테이지 배치 / 최소 HUD

기존의 일괄 양쪽 포대·측면 벽·허공 마름모 배치는 폐기했다. 1~3은 연습, 4/6/7/8/10/11/12는 스테이지마다 한쪽 포대만 배치하며 위협하는 점프 높이를 달리한다. 5/9/11/12는 실제 발판 끝에 낮은 가시를 두고, 진입 방향 반대쪽에 배치해 정상 착지를 막지 않는다. 포격 예고선과 맵 내 설명·스테이지명·비용·상태 문구를 숨기고 점프 횟수만 표시한다. 목표는 글자 대신 깃발로 표시한다. 사용량과 설정 정보는 맵 밖 탭/메뉴에 둔다.

배치 검증 중 9번 스테이지의 진입 가로막힘을 발견해 가시 위치를 수정했다. 108회 기본 경로 완주와 별도 36개 맵/난이도 조합의 포대 수(0 또는 1), 발사 방향, 중앙 안전 착지, 카운터 전용 HUD, 안내선 숨김을 검증한다. 최신 동작은 README의 스테이지 표를 따른다.


## 출발 제한 제거

사용자 요청으로 대포 맵의 최소 점프 잔액 조건과 충전 권유 문구를 제거했다. 모든 난이도에서 잔액 1회로 즉시 출발 가능하며, 실제 점프/회복 시 1회 차감만 적용한다. 이전 출발 필요 횟수 관련 기록은 폐기된 정책이다.

## 단계별 난이도 및 사용량 화면 재설계

- 1~5번은 4점프, 6~8번은 5점프, 9~12번은 6점프로 늘렸다. 후반은 좌우 이동 폭이 135~140pt까지 커진다.
- 같은 난이도에서도 스테이지마다 발판 폭을 기본 폭의 3.4%씩 줄인다. 가시가 있는 발판은 중앙 착지 여유를 유지하도록 최소 52pt, 그 외 최소 32pt를 적용한다. 난도는 폭뿐 아니라 이동 폭·연속 점프 수·포격 압박으로 구성한다.
- 포격 간격은 기본 간격에서 단계마다 0.075초 줄이고, 포탄 속도는 단계마다 5pt/s 높인다. 출발 잔액 제한은 추가하지 않았다.
- 후반의 점프 궤적이 HUD를 가리지 않도록 목표 발판과 상승 최고점을 화면 상단 아래에 맞췄다. 가시는 8×10pt로 줄여 좁은 발판의 정상 착지가 피격으로 처리되지 않게 했다.
- 사용량의 영어 표어, 대형 숫자 카드, 둥근 카드 테두리, 민트·주황 강조를 제거했다. 시스템 팝오버 배경, 기본 글꼴, 오른쪽 정렬 숫자, 얇은 구분선으로 정리하고 사용한 점프 횟수를 추가했다. 라이트/다크 모드는 시스템을 따른다.
- 108회 기본 경로 완주/531회 착지, 별도 포격·배치·소비·탭 검증 통과. 자동 완주는 클리어 가능성 검사이며 실제 체감 난이도 평가는 별도다.


## 순차 진행 / 레일 / 빙판

- 첫 성공 점프에 난이도를 고정하며 전체 12개 맵을 클리어해야 다시 선택할 수 있다. 새 난이도 선택은 진행을 1번으로 초기화하고 잔액을 보존한다. 잔액 부족으로 실패한 점프는 도전 시작으로 취급하지 않는다.
- 다음 맵은 현재 맵 클리어 후에만 해금한다. 메뉴 비활성화와 데이터 변경 함수 양쪽에서 검증하며 앱 재실행 후에도 저장된다. 이미 클리어한 맵은 다시 플레이할 수 있다.
- 자유 스테이지 선택이 가능했던 이전 저장 데이터는 임의 선택한 번호를 해금 진행으로 간주하지 않고 1번부터 시작한다. 토큰·소비 기록·캐릭터는 유지한다.
- 레일: 3번 2층에서 소개, 6번 2층, 8번 2/4층, 10번 3층, 12번 4층. 화면 경계 안에서 수평 왕복하며, 탑승자를 같은 변위로 옮긴다. 이동 중 상대 위치를 보간해 착지한다.
- 빙판: 5번 1층에서 소개, 7번 1/3층, 9번 2/4층, 11번 1/4층, 12번 3층. 가속·감속·역방향 제동과 공중 관성을 적용한다. 일반 발판은 기존처럼 키를 놓으면 멈춘다.
- 색과 레일 모양으로 발판 종류를 구분하며 맵 HUD는 점프 횟수 하나를 유지한다. 상단에는 진행 번호와 클리어 시 다음 버튼을 표시한다.
- 검증: 진행 잠금/전체 클리어 해제/새 도전 초기화/잔액 보존/재실행 저장을 별도 검사. 레일 탑승·동적 착지·차감·빙판 관성·일반 발판 정지를 통합 검사. 기존 108회 경로 검증은 동적 발판과 대포를 끈 정적 경로 검사이며, 신규 메커니즘은 별도 검사한다. 실제 플레이 체감·육안 검증과 자동 검증은 구분한다.


## 착지 후에만 재점프

공중 회복 점프, 코요테 타임, 착지 전 점프 버퍼를 모두 제거했다. grounded 플래그만 믿지 않고 발과 실제 발판/벽 윗면의 접촉을 확인한다. 피격 후 공중 연타·상승/하강 중 연타·발판 밖의 오래된 접촉 상태는 추가 점프나 차감을 발생시키지 않는다. 착지 전 입력은 버리고 실제 착지 후 새로 누를 때만 점프한다. 이전 공중 회복 관련 기획은 폐기한다.

## 자체 SVG 스프라이트

기본 도형을 직접 그린 SVG 8종을 제작했다. 발판 4종, 대포, 가시, 포탄, 깃발의 일관된 원본은 Assets/Sprites에 둔다. 외부 에셋/로고는 사용하지 않았다. 빌드 시 AppKit 오프스크린 렌더러로 3배 해상도 PNG로 변환하고 앱 리소스에 포함한다. 실행 중에는 SKTexture를 캐시하며 SVG/웹뷰 렌더링은 하지 않는다. 실제 래스터 출력의 대포·얼음·가시 및 전체 시트를 육안 점검했다. 충돌 영역은 유지했고 아트 로딩·기본 착지·레일/빙판·포격·탭 테스트가 통과했다.


## 클리어 안내와 후반 코스 확장

클리어 패널에 다음 버튼과 N / Enter 안내를 추가했다. 마지막은 완주 안내와 난이도 선택 버튼이다. 9~12번은 8/10/11/12점프로 확장했고 후반 정밀 발판은 난이도별 최소 48/36/26pt이다. 구간 입구(0/6) 착지 시에만 화면이 전환되며 점프 중에는 고정한다. 7번 이후에는 매 발판이 아닌 구간 시작점으로 실패 복귀한다. 다음 구간 발판을 HUD 뒤에 미리 표시하지 않는다. 기본 경로 108회 완주와 684회 착지, 레일/빙판/포격, 구간 전환/복귀, 클리어 패널/Enter/완주 버튼 검증이 통과했다. UI 테스트는 별도 임시 저장소를 사용하며 체험 잔액만 늘렸다. 자동 검증과 실제 체감 난도/화면 육안 검증은 구분한다.

## 2026-10-21 장애물과 어려움 재구성

어려움 1~8번은 별도 지그재그 경로(6~9회 점프)로 바꾸고 1번부터 회전 십자 가시, 시간제 발판, 붕괴 발판을 배치했다. 보통·쉬움은 붕괴 발판 3번, 시간제 발판 4번, 회전 가시 6번부터 등장한다. 회전 가시는 난이도별 크기·속도·높이가 다르다. 보라색 발판은 3.6초 주기 중 2.5초 동안 나타나며 소멸 직전에 깜빡인다. 균열이 있는 주황색 발판은 밟은 뒤 쉬움/보통 0.8초, 어려움 0.45초 후 사라지고 3초 뒤 복구된다. 시작·목표 발판은 사라지지 않는다. 정적 가시는 넓힌 발판의 중앙/왼쪽/오른쪽에 나누어 배치하며 소멸 발판과 겹치지 않는다.

이전 체크포인트 규칙을 폐기했다. 낙하·가시 접촉 모두 첫 발판으로 돌아가며 발판 주기와 포탄도 초기화한다. 레일 선과 양끝 표시를 제거했다. 게임이 숨겨지면 장애물 시간도 정지한다. 마리오의 Fire Bar와 Donut Block은 동작 유형 참고이며 코드·그림은 자체 제작했다.

검증: 36개 조합의 장애물 활성 구간에서 도약 시점·위치·수평 이동 지연·빙판 감속을 탐색해 착지 가능한 경로를 확인했다. 대포를 끈 개별 구간 검사이며 전체 캠페인 자동 완주 검사는 아니다. 회전 가시는 중앙 정적 가시와 인접한 구간 및 되돌아오는 구간을 피해서 배치한다. 정적 가시 발판은 이동 발판에서 제외해 가시만 허공에 남지 않게 했다. 기존 기본 점프/대포/이동 발판/사용량 UI 검증이 통과했고 어려움 1번의 실제 SpriteKit 렌더링을 확인했다.

## 2026-10-21 맵별 기능과 서체

맵별로 스위치 연결 발판(3/8/11), 열쇠로 골인 해제(5/9/12), 공중 바람 구간(4/7/9/10/12)을 나누어 배치했다. 열쇠는 실제 접촉으로 수집하며 소멸한 발판의 열쇠는 획득하지 않는다. 버튼은 해당 발판의 버튼 위치에서 접촉해야 켜지고 실패 시 모두 초기화한다. 게임 지도 HUD는 점프 숫자를 유지하고 선택 화면에서 맵별 공략을 안내한다. 세 단계마다 배경 팔레트를 달리한다. 기능 검증과 36개 조합의 기존 장애물 구간 검사, 승강/좌우 이동/빙판 검사가 통과했다.

눈누와 제작자 원문을 확인해 갈무리11 v2.40.4 한 종을 수정 없이 번들에 포함했다. OFL 1.1 원문·저작권 고지·제작자 제공 한국어 번역을 같이 배포하며 설정 메뉴에서 원문을 연다. OS 설치 없이 프로세스 안에서 등록한다. 게임 HUD/선택/클리어 서체에 사용하며 사용량 화면은 기존 시스템 서체다. 실제 패키지의 폰트 등록과 한글·숫자·화살표 지원을 확인했다.
